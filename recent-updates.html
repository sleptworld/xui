01 · CLOCK

全局帧时钟 FrameClock

一帧采样一次时间并冻结整帧，下游全部"读"这同一个 FrameTime。它是 presentation clock——只在真正产出帧时前进，所以离屏/卡顿是"暂停"而非"跳变"。 

pub struct FrameTime {
    index: u64,        // 第几帧（首帧为 1，ZERO 为 0）
    timestamp: Duration, // == Σ delta，恒等式即便 clamp 后也成立
    delta: Duration,     // 自上一帧，受 100ms 钳制
}

pub struct FrameClock { last: Option<Instant>, frame: FrameTime, max_delta: Duration }

impl FrameClock {
    pub fn tick(&mut self, now: Instant) -> FrameTime { // 正常推进，delta 被 clamp }
    pub fn hold(&mut self) -> FrameTime { // 离屏重绘：index++ 但 timestamp/delta 不动 }
    pub fn suspend(&mut self) { // 进入 idle；gap 变 0 delta }
}

要解决的两个老问题

同帧漂移

过去每个动画各自读 Instant::now()，同一帧里两个本该同步的动画会因帧耗时产生相对漂移。

离屏跳变

墙钟在窗口被遮挡时继续走，恢复时画面一下子跳到"墙钟走到哪"，而不是从停下的地方继续。

02 · TICKER

每帧回调 use_ticker

不是 timer，是帧循环自己的回调：每帧至多一次、拿到当帧 FrameTime、随窗口离屏而停。组件卸载即自动注销。 

// 推荐形态：模型在 HookRef 里，画布 invalidate —— 不重建组件
let model = cx.use_ref(Simulation::new);
let canvas = cx.use_memo(CanvasController::new);
let ticker = cx.use_ticker(move |frame| {
    model.update(|m| m.advance(frame.delta()));
    canvas.get().invalidate();
    Tick::Continue
});
// ticker.clone() 可被 play/pause 按钮捕获

关键设计

弱句柄

返回的 Ticker 是 Weak；钩子槽持有强引用，组件卸载即注销，遗留的句柄变 no-op。

回调每帧替换

不设 deps 列表：每帧 render 替换回调，始终捕获最新 render 的值。把"陈旧捕获"从默认行为变成不可能。

03 · NO WALL CLOCK

移除组件层的墙钟

组件运行时不再自己读 SystemTime。lane 饥饿截止期改用 SchedulerState::origin（单调 Instant，从 scheduler 创建起算）。 

// 旧：会倒退的墙钟
fn now_ms() -> u64 {
    SystemTime::now().duration_since(UNIX_EPOCH).unwrap_or(0).as_millis()
}
self.scheduler.mark_starved_lanes_as_expired(now_ms());   // ← 调用方传时间

// 新：单调钟，scheduler 自己读自己的 origin
struct SchedulerState { ... origin: Instant }
impl SchedulerState { fn now_ms(&self) -> u64 { self.origin.elapsed().as_millis() } }

pub fn mark_starved_lanes_as_expired(&self) { // 不再接收外部 now
    let now_ms = self.inner.borrow().now_ms();
    ...
}

04 · CANVAS

画布时间统一 CanvasFrame

画布绘制不再自己捕 Instant，而是从 CanvasPainter::time() 读帧时间。所有绘制在同一帧用同一时间步。 

pub(crate) struct CanvasFrame<'a> {
    pub size: Size<f32>,
    pub style: &'a ComputedStyle,
    pub theme: &'a Theme,
    pub scale_factor: f32,
    pub time: FrameTime,          // ← 新增
    pub gpu: Option<&CanvasGpuContext>,
}

// 矢量 painter 也补了 request_repaint —— 与 GPU painter 对齐
impl<'a> CanvasPainter<'a> {
    pub fn time(&self) -> FrameTime { self.time }
    pub fn request_repaint(&mut self) -> &mut Self { self.repaint = true; self }
}
// GPU painter 的推荐写法：起点存 state，之后都用帧时间戳度量
move |state: &mut Option<Duration>, painter: &mut CanvasGpuPainter| {
    let started = *state.get_or_insert(painter.time().timestamp());
    if painter.time().timestamp() - started < Duration::from_secs(2) {
        painter.request_repaint();
    }
}
05 · VISIBILITY

单一可见性闸门 is_animating

可见性只在一处施加。is_dirty 用 is_animating() 替代原来的两个独立布尔。请求本身照常记录，所以"回来"时恢复原状而非从头来。 

pub fn is_animating(&self) -> bool {
    self.window_visible
        && (self.has_running_style_animations()
            || self.has_animating_canvases()
            || self.tickers.is_running())
}

平台可见性来源

没有单一事件能表达"窗口能不能被看到"：

macOS / Wayland

发 WindowEvent::Occluded。

Windows / X11 最小化

不发 occlusion，而是 resize 到 0 + is_minimized。

refresh_window_visibility() 取三者悲观值（!occluded && !minimized && size>0），在 Occluded / Resized / Focused 都调用一次。从不可见转可见时再 request_redraw_if_dirty() 重启循环。 

// 停循环必须连时钟一起停 —— 这就是为什么 set_window_visible 收成 pub(crate)
pub fn set_window_visible(&mut self, visible: bool) {
    if !visible { self.frame_clock.suspend(); }   // 时钟也停
    self.app.set_window_visible(visible);
}
06 · SCROLL

程序化滚动 ScrollController

挂在可滚动 widget 上：widget.scroll_controller(controller.clone())。运行时绑定到 host 节点、保持 metrics 最新，并把请求推迟到下一帧布局后应用。 

pub struct ScrollMetrics {
    pub offset: Point,            // 当前偏移
    pub content_size: Size<f32>,  // ≥ viewport
    pub viewport_size: Size<f32>,
    pub max_offset: Point,        // 各轴最大偏移；不滚的轴为 0
}

impl ScrollController {
    pub fn scroll_to(&self, offset: impl Into<Point>) -> bool;
    pub fn scroll_by(&self, delta: impl Into<Point>) -> bool;
    pub fn scroll_to_start(&self) -> bool;
    pub fn scroll_to_end(&self) -> bool;
}

应用后会作为 ScrollSource::Programmatic 的 Scroll 事件回报——所以只监听 on_scroll 的组件（如 virtual_list）能跟上自己没发起的跳转。另：b44fd86 让 virtual_list 忽略冒泡上来的滚动事件。

07 · INVARIANTS

内部不变量上报 invariant!

host 树 / layout 树 / style 系统 / render 系统按同一 NodeId 索引。一处命中、另一处 miss 过去是裸 else { return }，bug 变成不可点的 widget 且日志里什么都没有。invariant! 在拿回 Option 的同时上报 miss。 

// 旧：静默吞掉
let host = self.hosts.get(id) else { return; };

// 新：控制流不变，但上报
let host = invariant!(self.hosts.get(id), "missing host for {id:?}");
// diagnostics.rs
pub(crate) fn report(file: &static str, line: u32, context: Arguments) {
    #[cfg(feature = "strict-invariants")]
    panic!("xui invariant violated at {file}:{line}: {context}");

    #[cfg(not(feature = "strict-invariants"))]
    log::error!("xui invariant violated at {file}:{line}: {context}");
}

f8557f3 · 打包进 build.rs
