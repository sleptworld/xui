Architecture walkthrough · 2026.10.19

从“重新描述一切”
到复用静态、补丁动态。

DSL 开始参与增量更新：编译期切分 UI，运行时保留 Fiber 的身份、生命周期与调度，让 host 的更新走更短的路。

阶段 0–3 已实现工作区快照 · 基于 HEAD fc67e61 + 未提交改动

本文以当前源代码为准，重点对比工作区与 HEAD。view!、Lanes、WIP、Prop<T> 等作为已有背景解释；Block Template 与 Signal 直接绑定仍是后续设计。交互区域为 JavaScript 机制模拟，不执行 Rust 或原生 XUI 渲染。

01 / 编译期

一个 DSL，三条路径

完全静态 → Hoisted。词汇表内的动态 host → Templated。其余 → 普通 builder。

02 / 数据所有权

描述可以共享，实例各自独立

WidgetProto 描述 UI；WidgetI 承载活实例。缓存同一描述、挂载多次成为安全操作。

03 / Fiber 与提交

少存副本，少做比较

Fiber 保存 host 身份与复用依据；样式、布局和 widget 留在 UiRuntime。相同模板直接比较 slot。

xui! / view!共享 Element AST
→
ElementDesc普通 / 提升 / 模板
→
Fiber / WIPLanes · reconcile
→
UiRuntimecommit · 活 host
→
增量后处理Style → Layout → Paint
讲解主线：先解决“共享描述会污染活实例”，再实现“静态子树跳过”，最后让“同调用点的动态 host 只比较 slot”。这三步存在依赖。

依据：template-slots.md §11–12 · fiber.rs / HostState

01 · Compile-time partition

宏不再只有 builder 展开。

两套语法先进入同一棵 Element AST，再依次尝试提升、模板化、普通展开。语法与类型检查仍然配合工作，但模板化已经引入明确的 host / 样式词汇表。

// JSX 风格
xui! {
  <row gap={8.0}>
    <text>{"Count"}</text>
    <text>{label}</text>
  </row>
}
// SwiftUI 风格：相同的中间表示
view! {
  row(gap: 8.0) {
    text("Count")
    text(label)
  }
}
源码示例
宏路径 · 预设案例推演


Hoisting：保守的语法判断
字面量、常量路径、元组、数组、共享引用、部分一元表达式和原始类型 cast 可静态化。函数 / 方法调用不被视为纯；含 if / for / match / let 的父子树不整体提升，内部静态子树仍可单独提升。
最大静态子树在每个调用点、每个线程首次使用时构造一次。这里的“静态”指描述固定，内部组件自己的状态更新仍能发生。
Template：受 schema 约束
目前支持 container / row / column / center / z_stack / grid / text。动态 key 单独处理；事件通过每事件一个的类型化函数获得闭包签名。
canvas / text_input / image / icon 不走模板路径；完全静态时仍先接受 hoisting 判断。未知小写 tag、泛型 tag、动态非词汇属性按普通方式构造。


实际 slot 粒度：动态文本是 content slot；动态样式合并成一个 Option<Box<Style>> 片段，并非每个样式属性一个独立标量 slot。第一个动态样式之后的所有样式 setter 都进入片段，保留覆盖顺序。


依据：element.rs / expand_value · hoist.rs · template.rs · xui-schema







02 · Ownership first
共享的是描述，挂载的是独立实例。


之前 · HEAD
描述与活 widget 共用 WidgetI
ElementDesc::Host
  └─ WidgetI: Rc<RefCell<Widgets>>
       ├─ 配置与样式
       └─ 输入框 / 交互中的实例状态

create_node → 直接持有同一个 WidgetI
缓存一份描述再挂载两次，可能令活节点共享内部状态；prepare 时取走 handler 也会改变被缓存的描述。
现在 · 工作区
WidgetProto → instantiate → WidgetI
WidgetProto: Rc<Widgets>
  ├─ instantiate() → WidgetI A
  └─ instantiate() → WidgetI B

UiRuntime host A / host B
  └─ 各自 Rc<RefCell<Widgets>>
共享描述保持可复用；每次挂载创建独立 host 实例。实例化由各 widget 的实现负责，交互信息单独提交给交互系统。


Fiber 的 host 记忆变轻了


HEAD 的 HostState当前 HostState实际意义
widget、taffy Style、ComputedStyle、layout、previous_layout移除这些副本；通过 node_id 访问 UiRuntimecommit 不再为每个 host 复制整份计算样式和布局快照
node_id、props_hash保留，并增加 proto、hoisted、template保存描述身份、提升子树身份，以及模板 base 和上次 slots
更新时比较完整描述同 proto 可按指针识别；同 hoisted 可跳过子树；同 base 可比较 slots按复用条件选择不同粒度的工作


Handler 不属于视觉属性相等性。即使 props hash 没变，也要在已重渲染的 host 上替换本次 handler；移除 handler 要清空旧回调。这个路径不额外标记视觉工作。


依据：widgets.rs / WidgetProto、instantiate · fiber.rs / HostState · component.rs / freeze_host_state、commit_handlers_if_host

04 · Fiber still owns identity
模板缩短 host 更新，Fiber 继续管理树。


Lanes：决定谁有工作
组件自身的 lanes 与 child_lanes 决定是否进入 begin work。Sync、连续输入、Default、Transition 等优先级仍由调度体系负责。
WIP：描述这次提交
WorkNode 区分 HostWork / ComponentWork / PortalWork，持有 current 绑定、children 与 effect。commit 后形成新的已提交 Fiber 状态。
Commit：写入保留树
PLACEMENT / MOVE / UPDATE 与删除列表决定树修改。UiRuntime 的 commit 接口负责创建、定位、更新和移除活 host。


即使提升描述的 Rc 相同，只要其内部组件存在匹配 render lanes 的排期工作，运行时仍会下降处理。Hoisted 不会冻结 hooks 状态。


演示：有 key 的兄弟重排，host 身份保持
初始顺序 A → B → C。算法维护 last_placed_index；旧下标小于该值的复用项带 MOVE。这里仅模拟同类型、有 key 的三个兄弟。
所有节点已经挂载；每个 key 对应固定的 host ID。


无 key 时按位置匹配；key 相同还要满足类型兼容。key 改变会影响节点复用，动态 key 并非普通视觉属性 patch。


依据：component.rs / reconcile_children、find_reusable_child_fast、should_render_component · lanes.rs。本节调度与身份机制是现有体系背景，不宣称均由本次未提交改动新增。

release · 五次运行的逐行最小值


耗时 / ms · 越短越好 · 每个规模内使用同一线性比例


现在减少了什么
静态树首次构造后跳过重建与深层 reconcile；同 base 的模板避免完整描述构造和 props hash，改为比较 style / content slots，直接 patch 活 widget。
并非零分配：children、样式片段、handler 仍有构造和存储成本；文字变化还可能触发文本排版。
一次重要的布局回退
文档记录 Style 为 2480 字节。最初内联样式 slot 曾把 ElementDesc / WorkNode / Fiber Node 膨胀到数 KB；现用 Box 限制枚举体积。
记录中的 TemplatedDesc 为 144 字节，ElementDesc 为 152 字节。尺寸与耗时均是当时构建记录，不是浏览器或本页实时测量。

06 · What changes for authors
迁移重点是组件名字与扩展边界。


组件函数 snake_case，tag PascalCase
#[component]
fn date_picker(value: &String) -> ElementDesc {
  view! { text(value.as_str()) }
}

// 之前的 <date_picker /> / date_picker(...)
// 改用生成的 PascalCase tag：
xui! { <DatePicker value={value} /> }
view! { DatePicker(value: value) }
更新导入、重导出、组件别名和 builder 调用；例如 Select / ComboBox / Sheet。host tag 保持小写。
扩展仍有普通 builder 路径
新样式属性在 style_props! 加 setter；若符合模板化语义，同步 xui_schema::STYLE_PROPS。一致性测试约束这两张表。
新 host构造函数、Styled 与 IntoElement 决定基本 DSL 能力；加入 HOST_TAGS 前需验证实例状态与同名固有方法语义。
检查元素形状ElementDesc 新增 Hoisted / Templated 变体。resolved() 看穿 Hoisted；需要普通 host 描述时使用 to_host()。
